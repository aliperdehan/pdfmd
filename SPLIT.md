# Splitting pdfmd.py into packages under lib/

Entry 3fi. The rule behind it is CLAUDE.md's "pdfmd.py holds only the core". Phase 1 (2026-11-09 and 10, 3.33.0 to 3.33.40)
moved 37 packages out of `pdfmd.py`; phase 2 moves what is left, so that `pdfmd.py` ends as a launchpad of about 600 lines:
its imports, the binding block, the state that must stay a module global, `main()`, the Python API and `PDFMD_VERSION`.
Phase 2 was planned on 2026-11-10 at 3.33.74; its move list was regenerated by name at 3.33.187 (the same 975 top-level
names as at 3.33.74, 42 of their bodies changed) and is below, with wave 0's changes to the binding block applied. The
tools read this file: `scripts/split_spec.py KEY` and `scripts/split_move.py KEY` find a move's section by its key under
`## Phase 2:`; phase 1's sections, further down, are the record (`--phase 1` reads them). Where code comments or CLAUDE.md
say "SPLIT.md, step N", they mean phase 1's pattern, under phase 1 below.

## Phase 2: the moves, in order

### What phase 2 does differently

Phase 1's pattern (below, under phase 1) still holds: one package per commit, a pure move, `core.NAME` for every pdfmd
name, packaging in three places, `split_check`. Phase 2 adds five things, all in place since wave 0:

1. **One shared `core`** (3.33.188, decision D2). Every module says `from pdfmd_base import core`; `core` passes every
   attribute read, write and deletion on to pdfmd, which binds it to itself before it imports any package (the first
   binding wins). A package imported any other way (a `-j` worker, one package importing another, a test) has its `core`
   too, which is what lets packages load only when a run needs them.
2. **The names table** (3.33.189). A moved name read from outside its module is one word of a table line in `pdfmd.py`,
   `names("pdfmd_x.role", "a b c")` (`pdfmd_base.names_into`, filling `DEFERRED_NAMES`): `pdfmd.a` is then the module's
   own object, loaded on the first read and kept in pdfmd's globals, so `.cache_clear()`, class attributes and
   `mock.patch.object(pdfmd, "a")` work as they did, and a later read costs a plain lookup. Because pdfmd keeps the first
   object, a module never rebinds a name it serves (state that is rebound stays in `pdfmd.py`), and a test patches the
   name on pdfmd, not on the package. `names()` refuses, when `pdfmd.py` loads, a word that is not a name or a name the
   table serves from another module. A stand-in (`a = deferred("pdfmd_x.role", "a")`) stays only for a moved function that
   code still in `pdfmd.py` calls bare, and a plain import only for `pdfmd_base`. A name is never both bound in `pdfmd.py`
   and in the table, each name is in one table line, and the table read from the source is the one pdfmd has
   (`tests/test_split.py`).
3. **Callers first.** `run_main` moves first, then the build, then what they called, the hubs (`display_path`,
   `config_options`) last: moved code reads a helper as `core.X` whether the helper has moved yet or not, so few bindings are
   needed in between (71 in all by the move list's count; helpers first would need about 370), and the biggest moves are
   the ones every `split_check` build goes through.
4. **The tools.** `scripts/split_spec.py KEY` (3.33.187j) reports what a move needs: where the code goes, what it reads
   as `core.X`, the state it writes, every kind of test patch, what is read when a module loads (both ways), cached
   functions and their `.cache_clear()` callers, `__file__` / `__name__` / `globals()`. `scripts/split_move.py KEY`
   (3.33.187k, decision D5) does the mechanical part and checks itself (each moved statement parses back to the original's
   AST with exactly its substitutions); it refuses, and writes nothing, what needs a decision.
5. **The safety net** (3.33.187i, `tests/test_split.py`, `SafetyNet`): every `core.NAME` in lib/ is something pdfmd has,
   every table entry and stand-in names something its module has, no name is both a pdfmd global and a table entry, no
   code in lib/ binds a bare name that is one of pdfmd's state names (a `global X` lost in a move makes `X = ...` a local),
   and (3.33.189) no module rebinds with `global` a name it serves to the table.

Decisions (the author, 2026-11-10 and 11): D1, `run_main` moves whole, to `pdfmd_run`; D2, one shared `core`; D3, the
module docstring becomes `docs/reference.md`, read with `pdfmd --doc reference` (wave 5); D4, the 15 package names above;
D5, the mover tool; D6, the full suite twice, after move 5 and at the end; D7, moves 41-47 (single constants) in one commit.

### The pattern for every move (phase 2)

0. **Clean tree, then the spec.** `git status` clean at HEAD; `python3 scripts/split_spec.py KEY`.
1. **One section per commit, a pure move** (moves 41-47 together, D7). Each is a 3.33.x patch with its own changelog entry
   and `PDFMD_VERSION` bump; a bug found on the way is fixed in a commit of its own.
2. **The tool.** `python3 scripts/split_move.py KEY --dry-run`, then without `--dry-run`. It writes the module (a new
   `lib/pdfmd_x/__init__.py` for `pdfmd_x`, `lib/pdfmd_x/role.py` for `pdfmd_x.role`, appended when it exists), the table
   line and the stand-ins. Read what it refuses and the comment blocks it carries (a section's banner may sit right above
   a definition); do the refused parts by hand and list them in the changelog entry. It needs Python 3.12 or later.
3. **How the code reaches pdfmd.** `core.NAME` for every pdfmd name, read when the code runs; never `import pdfmd`, never a
   copy taken at import. A package imports another directly only for what it needs when it loads: a decorator (`timed`,
   `noted` from `pdfmd_base`), a constant built from another, a base class. Calls to a name that tests patch on pdfmd go
   through `core.` even inside the move (the tool does it). A new module starts with `from __future__ import annotations`.
4. **pdfmd.py.** The moved code goes, with the comment blocks that belong to it. `wc -l pdfmd.py` before and after goes
   into the entry; `pdfmd.py` only shrinks.
5. **Packaging.** A new package goes into `pyproject.toml` (`packages` and `[tool.setuptools.package-dir]`) and
   `PACKAGES` in `scripts/build_zipapp.py`; `test_packaging` fails until it does.
6. **Start-up.** No package may newly load at start: compare the `sys.modules` listing of CLAUDE.md before and after, and
   `python3 scripts/pdfmd --version` interleaved with HEAD (best and median).
7. **Proof.**
   - `ruff check --select F --force-exclude --exclude pdfmd_inkmd --exclude pdfmd_yaml pdfmd.py lib/ scripts/ tests/`.
   - The move's tests (its section's list is a floor; add the feature's own) and the always-run set: `test_packaging`,
     `test_setup`, `test_docs_consistency`, `test_compat`, `test_probes`, `test_serve`, `test_launcher`, `test_jobs`,
     `test_split`.
   - `python3 scripts/split_check.py` with `--extra 'NAME:ARGS'` builds that reach the moved code through its real call
     site (a table entry is only exercised when something reads it); read its BOTH FAILED lines.
   - The full suite after move 5 and after the last move (D6).
8. **Docs** that say where code lives change in the same commit.
9. **Progress.** When a move is done, its heading here gets "done in 3.33.x".

## Phase 1: the packages, in order (done: 3.33.0 to 3.33.40)

### How the table was made

- The seeds are the names of the first survey. A definition joins a package when every definition that uses it is in that
  package, repeated until nothing changes. A definition used by two packages, or by code that stays, stays.
- Never moved: `main`, `run_main`, `convert_one`, `_convert_one_core`, `convert_file`, `convert_text`, `PdfmdError`.
- A constant moves with a package only when that package alone reads it and nothing rebinds it. State rebound with
  `global` (the `*_CLI` settings, `LAST_*`, `VERBOSE_OUTPUT`, the probe caches) stays in `pdfmd.py`.
- The lists are names, not line numbers, because lines shift with every move. A change to the table during the moves is made
  here, in the commit of the move it concerns.
- SPLIT.md's `pdfmd_cli_parser` is `pdfmd_args` (the `pdfmd_cli` namespace is a 4.0 question). The other names are the
  ones chosen on 2026-11-08: `pdfmd_assemble`, `pdfmd_parts`, `pdfmd_attach`, `pdfmd_tex`, `pdfmd_pdfimages`,
  `pdfmd_compat`, `pdfmd_routing`.

### The pattern for every move (phase 1)

0. **The spec first.** `python3 scripts/split_spec.py pdfmd_x` reads the package's section below and the source as it is
   now, and prints where each name is, the pdfmd names to read as `core.X`, the re-exports, the test patches that matter
   and the names bound twice at the top level of `pdfmd.py`. A name bound twice stays where its binding in force is (the
   later one), whatever the table says; the earlier, dead binding is removed in a commit of its own.
1. **One package per commit, a pure move.** The tree is clean first. The first move is 3.33.0, each later one 3.33.x,
   with its own changelog entry and `PDFMD_VERSION` bump. A move changes no behaviour; a bug found on the way is fixed in
   a commit of its own (the author's leave, 2026-11-09).
2. **Where the code goes.** A new package: `lib/pdfmd_x/__init__.py`. An existing package: a module of its own beside
   what is there (`lib/pdfmd_x/<role>.py`), unless the moved code is small. The text is moved as it is; only names change.
3. **How it reaches pdfmd.** The package reads `core` from lib/pdfmd_base (`from pdfmd_base import core`, since 3.33.188;
   phase 1 gave each module a `core = None` that `pdfmd.py`'s `bind_core()` set): one object for every package, bound to
   pdfmd when `pdfmd.py` loads, and the first binding wins, so a second copy of pdfmd (a script run imports nothing as
   `pdfmd`, but a stray `import pdfmd` would make one) never re-points it. The re-exports are in the block after
   `pypdf = lazy_import("pypdf")`. `pdfmd.py` needs its packages
   (the author, 2026-11-09): the block starts with a check that stops a copy without `lib/` with one line, so a new package
   needs no fallback for a missing import. The new `__init__.py` starts
   with `from __future__ import annotations` (Python 3.9 reads the moved signatures' `str | None` only with it). Every pdfmd name the moved code uses (a helper, a constant, state)
   is read as `core.NAME` when it runs: never `import pdfmd`, never a copy taken at import time. Calls between moved
   functions are direct, except calls to a name that a test patches (`mock.patch.object(pdfmd, ...)`): those go through
   `core.`, so the patch still reaches them. Each package's section lists them.
4. **pdfmd.py.** The moved code is deleted. A re-export (`from pdfmd_x import a, b`, beside the binding) brings back every
   moved name that `pdfmd.py` itself, a test or a `lib/` module reads, so `pdfmd.a` keeps working. A lazy loader
   (`x_module()`) that only served the moved code goes. For a package that `pdfmd.py` does not load at start, the
   re-export is deferred (step 6).
5. **Packaging.** A new package goes into `pyproject.toml` (`packages` and `[tool.setuptools.package-dir]`) and into
   `PACKAGES` in `scripts/build_zipapp.py`; `test_packaging` fails until it does.
6. **Start-up time.** A plain re-export makes the package load at every start. Heavy imports stay inside functions;
   `python3 scripts/pdfmd --version` must not get slower (interleaved runs of HEAD and the move, best and median).
   - **New packages** hold only the moved code, cost a fraction of a millisecond, and are re-exported plainly.
   - **An existing package that `pdfmd.py` does not load at start today** is deferred, whatever it costs: the moved
     code goes into `lib/pdfmd_x/<role>.py`, and importing that runs the package's `__init__`, which loads the rest of
     the package (measured 2026-11-09 on top of pdfmd's own start: `pdfmd_serve` 17 ms, as it brings `http.server` and
     `ssl`; `pdfmd_office` 21 ms; the other fourteen 0.2 to 3.5 ms each, about 25 ms together). In the binding
     block, each moved function that `pdfmd.py` calls or a test reads gets a stand-in,
     `serve_command = deferred("pdfmd_serve.commands", "serve_command")`, which loads the module on its first call,
     and calls the real function (the module's `core` is pdfmd_base's); `pdfmd.py`'s own calls keep their bare names. A moved
     constant or class that a test or `lib/` reads as `pdfmd.X` goes into `DEFERRED_NAMES` instead
     (`DEFERRED_NAMES.update(_PANDOC_EXTENSIONS="pdfmd_flat.probe")`): the module's `__getattr__` (PEP 562) loads the
     module on the first read and returns the package's own object, so `mock.patch.dict(pdfmd.X)` still reaches it.
     `split_check`'s default builds may never reach a deferred call, so each deferred move adds an `--extra` build (or a
     timed hand run) that goes through the real call site.
7. **Proof.**
   - `ruff check --select F --force-exclude --exclude pdfmd_inkmd pdfmd.py lib/ scripts/ tests/` (the CI line).
   - The package's tests (below) and the always-run set: `test_packaging`, `test_setup`, `test_docs_consistency`,
     `test_compat`, `test_probes`, `test_serve`, `test_launcher`, `test_jobs`.
   - `python3 scripts/split_check.py` does the next two checks in one run: "before" is HEAD in a temporary worktree,
     "after" the working tree with the move uncommitted (`--extra 'NAME:ARGS'` adds a build of the package's feature,
     `--extra 'NAME!:ARGS'` one that must fail; any other build that fails in both trees is reported, BOTH FAILED, and the
     result is not SAME; `--real-data` for builds that need installed tools). Nothing in `pdfmd.py` or `lib/` is edited
     while it runs.
   - `--help` and every `--help TOPIC` byte-identical before and after.
   - `--verbose` output identical before and after (the trees' paths, temporary names, times and time stamps aside; a `-j` run's lines in any order) on a fixed
     set: one document to PDF, `--to html`, `--to docx`, `-r` on `examples/book`, `-b -j 2`, and the documents that use
     the package's feature. The baseline is taken before the first edit, with the tree clean.
   - The full suite once, after the last move (the author, 2026-11-09), not per move.
8. **Docs** that say where code lives (CLAUDE.md, README, docstrings) change in the same commit.
9. **Progress.** When a package is done, its heading here gets "done in 3.33.x (commit)". When all are done, phase 2 is
   planned and this file is rewritten for it.

The order goes from the smallest risk to the largest. Wave 1 sets the pattern for a new and for an existing package; the
hard packages come last, when the pattern is proven. "Tests" are the test modules that name the package's definitions or
its feature, run in addition to the always-run set.
